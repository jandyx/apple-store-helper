# 有货后 API 自提下单（实验性）

## 当前状态

实现已接到原监听器：不是第二个 `watch` 进程，不用页面点击回放，也不处理付款。
**完整链路目前仅通过合成 HTTP 契约测试，尚未完成真实订单核对页和最终提交验收。不要将它当作已验证的抢单工具。**

真实证据（2026-10-23）：Go 已校验购物袋并在明确隐私授权后走通官方访客继续、POST 结账 bootstrap、直接选择 R639、取货时段，进入真实提货联系人页。测试机为 `MJTF4CH/A`（18 Pro 512GB 冰川蓝色），没有发送搜店请求，也没有创建订单或付款。
这证明本次会话可省掉搜店步骤，**不代表正式 Runner 已自动切换为免搜店或访客模式**。正式配置仍只接受 Duo；不会自动登录或代为接受新的隐私声明。联系人、付款类型、真实订单审核仍需继续验收。

```text
现有库存接口 → 同一轮有货命中 → 消费一次性武装
   ├─ 原有通知、声音、记录（保留）
   └─ 独立 HTTP 会话 → 核对商品价格/购物袋 → 必要时加购一台
          → 选择自提及精确门店 → 时段 → 提货联系人 → 支付类型
          → 严格核对页验证
             ├─ review：停止，不提交
             └─ submit：先落盘 submission_unknown → 最终 POST 一次
                        → created 或保持 unknown，绝不自动重试
```

未知模型/字段、登录失效、541/HTML、其他购物袋商品、数量不符、超价、门店/联系人/支付类型不符都会停止。
不会删除购物袋中的商品或调整数量；空袋可以加一台，已有唯一正确商品则复用。
演练 **不是只读**：会进入结账、可能加购并填写资料，但不会最终提交。真正只读检查见下方 `-check-order-session`。

## 支持范围

- 中国大陆 iPhone Duo 256GB / 512GB、夜空色 / 星光白色四款配置。
- 配置中精确指定一个 SKU、允许的门店列表、完整省/市/区、金额上限（整数分）、微信或支付宝类型。
- 同轮多家店命中时按配置的门店顺序选择一家；每次“开始”最多尝试一次。
- 其他地区/机型继续走原监听提醒，不会尝试拿不匹配的商品下单。
- 新增代码不增加 Go 依赖；下单时不启动浏览器、不访问 Chrome Cookie 数据库、不读取密码。

## 在 App 中填写和保存提货资料

在主界面的“API 自提下单”区域点击 **“填写／编辑提货资料”**。仅提醒模式下也可以填写，不需要先武装 API，也不必在聊天里发送资料或手写联系人 JSON。

- 姓氏、名字、联系邮箱、手机号；证件字段只填号码后四位，官网未要求时可以留空。
- 手机号和证件后四位默认遮挡；重新打开会回填已保存内容，关闭时清空编辑器中的显示内容。仅编辑或关闭不会保存。
- 点击“保存到本机”才落盘。默认位置为用户配置目录下的 `apple-store-helper/private/pickup-contact.json`；macOS 即 `~/Library/Application Support/apple-store-helper/private/pickup-contact.json`。
- 文件 `0600`、私有目录 `0700`，采用原子替换；**是本机未加密文件，不是钥匙串或云同步**。资料不写普通设置、日志或通知。只支持 macOS/Linux 私有保存；Windows 尚待原生文件保护验收。
- 保存或确认清除会暂停监听、关闭 API 模式并解除本次武装；若同一应用中已有 API 尝试正在执行，会拒绝修改。保存绝不会启动监听或下单。
- “清除已保存资料”需要确认，只清除当前资料文件，不修改 Apple 账号、收藏或已创建订单。

API 配置可省略 `contact_file`，程序和同用户的 CLI 会读取上述 App 保存的默认资料。如果已选配置显式指定 `contact_file`，编辑器会读写那个文件；相对路径仍相对于 API 配置目录。该目录须私有，链接或不安全权限的文件会拒绝，不会悄悄写到别处。编辑器会显示实际保存位置。

保存资料不代表完整购买链路已验收。证件后四位的真实审核回显未验证前，含此字段的自动提交仍被阻止；只能继续演练。

## 私有文件

配置、会话和联系人 JSON 必须为本机私有常规文件（POSIX 下 `0600`），不应放入 Git 或推送消息。
GUI 原设置文件只记配置路径；不会保存 Cookie、联系人或自动提交武装状态。

配置示例（示意，不代表自动启用；门店地区必须与自己的目标一致）：

```json
{
  "session_file": "./session.json",
  "state_dir": "./order-state",
  "sku": "MK2Q4CH/A",
  "store_ids": ["R639"],
  "province": "广东",
  "city": "广州",
  "district": "天河区",
  "max_total_cents": 1799900,
  "payment": "WECHAT"
}
```

会话由本人授权的 Apple 会话导出，不复制整个浏览器资料。格式如下；示例值无效，切勿公开实际值：

```json
{
  "user_agent": "导出时的实际 User-Agent",
  "cookies": [{
    "name": "实际 Cookie 名称", "value": "私密值",
    "domain": ".apple.com.cn", "path": "/", "secure": true,
    "http_only": true, "expires": 0
  }]
}
```

保留每个 Cookie 的 domain/path/expiry 和 host-only 语义：前导点表示域 Cookie，无点表示精确主机 Cookie。
合法的空 Cookie 值保留，不能把 Cookie 简化成发给所有主机的固定请求头。只接受限定 Apple 商店域名及 Secure Cookie。

联系人应在 App 中显式填写并保存，不能从“账号登录成功”推断取货资料正确。需要手动维护文件时，格式如下：

```json
{"first_name":"本人名字","last_name":"本人姓氏","email":"本人邮箱","phone":"本人手机号","id_last4":"实际证件后4位"}
```

上面的示例是占位说明，不能直接运行。真实 CN 页面启用证件字段时，还需要政府颁发证件号码的 **后四位**；`id_last4` 只能是 4 位 ASCII 字母数字，不接受完整证件号或掩码。未启用该字段的旧模型可省略此项。

每个覆盖字段都必须唯一匹配当前提货人模型；手机号兼容已观察到的 `fullDaytimePhone`，以及旧契约的 `mobilePhone`，两者同时出现会拒绝。最终核对页仍需确认。**证件后四位在真实审核页的回显尚未验收，因此配置含 `id_last4` 时，`submit` 模式会在网络请求前拒绝；仅可继续 `review` 验证。** 不会为了继续而填写伪造资料或跳过未知审核字段。

## 使用入口

仅校验会话能读取购物袋（不查库存，不进入结账、不加购、不提交）：

```sh
go run ./cmd/apple-store-helper-cli -check-order-session /absolute/path/session.json
```

此检查成功 **不等于** 已登录结账、不等于有货或可以下单。

另有明确会进入结账会话的协议诊断参数 `-prepare-order-session`，必须同时指定 `-prepare-order-sku` 和 `-prepare-order-cap-cents`。
它只接受已有唯一正确手机的购物袋，不加购、不选门店、不填写资料、不提交订单，返回首个已识别阶段或停止原因。

GUI：在“API 自提下单”选实验模式及配置路径，然后手动点“开始”。默认仅提醒；每次重启回到仅提醒。
选择“自动提交”后，还须在开始时核对 SKU、允许门店、数量和金额上限并确认。
“停止本次 API 尝试”会取消/解除武装；普通“暂停监听”不会取消已经在进行的结账。
订单处理中不会再自动打开购买链接，避免同时操作同一购物袋。

CLI 演练示例（**会进入结账，勿在未完成协议验证时照抄运行**）：

```sh
go run ./cmd/apple-store-helper-cli -area cn -store R639 -product MK2Q4CH/A \
  -auto-order-config /absolute/path/order.json -auto-order-mode review -stop-on-hit
```

`-auto-order-mode` 默认 `off`；明确改为 `submit` 才允许创建真实订单。`-use-gui-config` 不会恢复提交武装。
`-once` 只做库存查询，拒绝与下单模式同时使用。CLI 会等订单尝试结束，不再按固定三秒强行退出。

## 防重复和恢复

状态目录内的跨进程锁覆盖整个尝试；最终 POST 前先同步落盘 `submission_unknown`。
请求超时、崩溃、无法识别订单结果、再次启动、换门店或型号，都不能绕过已有提交记录。
任何已有提交记录都须人工核对 Apple 订单后再决定下一步；**不要为了重新抢购而盲目删除状态文件**。
点击取消发生在最终提交附近时，不保证服务端未创建订单；仍以 Apple 订单记录为准。

Windows 主程序仍可构建和正常监控，但 **API 下单功能明确不支持 Windows**，在配置验证时拒绝；待原生 ACL、目录持久化和恢复机制验收后再开放。

